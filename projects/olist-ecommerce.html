Olist E-Commerce End-to-End Case Study

SQLite (real SQL joins) · Python (pandas, SciPy, RFM) · Power BI (7-table relational model, DAX) · Brazilian e-commerce, Oct 2016–Aug 2018

View Code on GitHub ← All Projects
Leadership wanted an end-to-end view of an e-commerce marketplace: revenue, delivery, sellers, and customers. The standard playbook here would be to build an RFM model and target retention, but only 3% of customers ever order twice, so that framing doesn't hold up. The real lever turned out to be first-order delivery reliability, worth R$1.16 million in order value sitting in late shipments.

The Problem

Leadership wanted one end-to-end view: what's driving revenue, where deliveries are failing, which sellers are underperforming, and which customers are actually worth retaining. This meant answering what the revenue trend looks like, where delivery is failing and whether it actually matters to customers, which sellers and categories are winning or losing, and critically, whether "retention" is even the right frame for this business.

Decisions & Approach

  • A real relational database, not a flattened CSV. All 9 source CSVs loaded into an actual SQLite database with indexes on the join keys used repeatedly.
  • 5 SQL queries saved separately, and actually executed, not hand-copied results, monthly revenue, delivery stats, seller leaderboard, category revenue, payment breakdown.
  • Bottom-seller ranking required ≥5 orders, a documented judgment call so one bad order can't make a low-volume seller look artificially terrible.
  • RFM segmentation built with relative quartiles, Recency, Frequency, and Monetary each split into quartiles and mapped to Champions / Loyal / Potential / At-Risk / Lost.
  • Repeat-purchase rate checked explicitly, not assumed, which is exactly what surfaced the 3% headline finding instead of it hiding inside a routine RFM run.

What the Data Showed

Only 3.0% of customers ever place a second order. Because RFM's Frequency dimension is nearly binary (1 order vs 2+) for almost everyone, "Champions" and "Loyal" segments mostly reflect big first-order spend, not real repeat loyalty, stating that plainly reframes the whole customer strategy. Meanwhile, delivery lateness is a real, quantified driver of bad reviews: on-time deliveries average 4.29 stars, late ones average 2.27, a statistically significant gap (t=100.97, p<0.000001) worth R$1,158,921 in order value. Cross-state shipping nearly doubles the late-delivery rate (7.9% vs 4.5%), a concrete, targetable logistics finding rather than a guess.

Recommendations

  1. Reframe the customer strategy around first-order delivery reliability, not retention campaigns.
  2. Prioritize logistics fixes on cross-state routes specifically, a clean, targetable segment.
  3. Audit the specific top-10-revenue seller with a 3.35 average review, high volume is masking a satisfaction problem.
  4. Treat "Champions"/"Loyal" RFM labels as spend-tier labels, not loyalty labels, when presenting to stakeholders.

Technical Build

Seven related Power BI tables (orders, order_items, customers, sellers, reviews, payments, and a precomputed RFM table) mirroring the real SQL joins, not one flat CSV. A real bug hit and fixed live: two measures for cross-state vs same-state late rate returned identical numbers, because Power BI only lets filters flow one way across a many-to-one relationship by default. The fix was setting that relationship's cross-filter direction to Both in Model view.

Total Revenue        = SUM(order_items[price]) + SUM(order_items[freight_value])
Avg Delivery Days    = AVERAGEX(orders, DATEDIFF(orders[order_purchase_timestamp], orders[order_delivered_customer_date], DAY))
% Cross-State Late   = CALCULATE(AVERAGE(orders[is_late]), order_items[cross_state] = 1)
% Same-State Late    = CALCULATE(AVERAGE(orders[is_late]), order_items[cross_state] = 0)

Limitations

  • The 3% repeat rate is structural to this 2016–2018 window, some "one-time" customers may have ordered again outside it.
  • RFM quartile cuts are relative to this dataset, not fixed business thresholds.
  • Delivery-delay-vs-review correlation is association, not proven causation.
  • Cross-state late-rate finding doesn't control for actual shipping distance.
